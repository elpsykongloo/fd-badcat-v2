# Demo 跨文本、句长与 seed 的自动诊断

当前决定：保留 chelsie、seed42 和 native Talker 修复，不新增线上生成机制。离线评测按句长分组，短句额外报告固定多句聚合分数，并保留每句分数与 F0。不能用未校准的单句 cosine 阈值自动判定换人，也不能通过聚合隐藏异常单句。

## 固定的实验条件

`scripts/check_demo_voice_cross_text.py` 使用4组自造中文内容，每组短答、中句、长句互为文本前缀，共12个不同文本；分别用 seed42/43 合成，最后再合成4个 seed42 中句作穿插恢复，共28次。四组内容覆盖确认、安抚、提问、叙述，但不是独立随机抽取的人类对话样本。

全程单机串行调用，生产 seq4 配置，native Talker 设置固定，无追踪、无其他 GPU 工作负载。服务日志确认 `bf16_reduced=False bf16_split_k=False`；speaker 与 seed 回执由流式客户端校验。离线嵌入在 Omni 停止后运行，继续使用作者最终 LMFT 权重、FP32、batch1 和原有预处理，不调模型或计分参数。没有真实用户音频、物理设备或人工评分；不是论文延迟、正式 SV 或冻结 test 结果。

另取4条 seed42 长音频的首尾1/2/4秒，共24个固定片段，无 VAD、补齐或挑选。首尾片段不重叠；片段与整段比较存在包含关系，不能与独立音频对等同。该对照同时混合时长、音素、静音和时间位置的影响，不证明长录音内部音色恒定，也不能将全部下降归因于嵌入模型。

合成前写入 `exp/web_demo/voice_cross_text_v1/protocol.json`：52段评测输入、112个预声明比较。所有合成与片段均保留，无排除；共享参考、嵌套文本和重复 seed 使比较相互依赖。没有异说话人负样本、身份阈值或人类自然度结论。

## 结果

| 句长 | 实际时长 | seed42 跨文本 cosine 均值 / 最低 | seed43 跨文本均值 | 同文换 seed 均值 |
| --- | --- | --- | --- | --- |
| 短 | 1.15–1.39s | 0.639748 / 0.546831 | 0.687115 | 0.738756 |
| 中 | 6.07–9.70s | 0.838789 / 0.810905 | 0.863053 | 0.867755 |
| 长 | 16.89–20.68s | 0.912680 / 0.886998 | 0.893444 | 0.921967 |

每个固定 seed / 句长有4段、6个全配对；同文换 seed 每种句长4对。seed43在短/中句的跨文本均值较高、长句较低，不能据此挑一个“最优 seed”或宣布身份改善。更长输入分数较高，但时长和内容一起变化，并非单因素因果试验。

| 同一长录音的固定片段 | 首尾片段 cosine 均值 / 最低（4对） | 片段对整段均值（8对） |
| --- | --- | --- |
| 1s | 0.536341 / 0.371270 | 0.737631 |
| 2s | 0.740900 / 0.667658 | 0.848499 |
| 4s | 0.863782 / 0.841284 | 0.924743 |

这说明低短句分数不是独立请求漂移的特异证据，不能把并发同文测试中的接近1直接当作跨文本目标。长句与长句也有剩余差异，但没有已知身份正负对照，无法量化其中多少是生成变化、多少是表征对内容的敏感性。

4/4串行恢复 PCM 完全一致，嵌入均为1；评测器穿插52段后重提第一段，最大绝对差为0。固定 seed 的同文可复现与跨文本差异是两件事。

严格 ASR 26/28匹配；两条失败完整保留：`f3-long-s42` 的“街上”被回读为“肩上”，`f2-medium-s43` 的第一问句回读多了“啊”。不能仅凭单个识别器断言合成漏字或多字。换 seed 的同文 F0 中位数绝对差，在短/中/长三组的中位数分别约1.95/1.48/1.52半音；沿用简单自相关算法，可能有倍频/清浊误差，F0不是说话人身份判据。

## 探索性补充：固定短句聚合

看到长度效应后，另写 `aggregation_protocol.json`，将每个 seed 的全部4条短句严格按组0/1/2/3拼接，不加间隔、不裁剪、不重复、不选高分片段。没有新增合成。它是探索性补充，不冒充事前预注册的确认试验。

两条拼接音频分别5.095/5.255秒。相对相同4条 seed42 长音频：

| 输入 | seed42 均值 | seed43 均值 |
| --- | --- | --- |
| 单个短句，全部短×长配对，各16对 | 0.678529 | 0.732700 |
| 固定4短句拼接×长句，各4对 | 0.839977 | 0.865476 |

两条拼接音频之间 cosine=0.894582，只有1对，不是可靠性统计。聚合同时增加内容覆盖和时长、引入拼接边界，还可能平均掉真实逐句漂移；因此只作补充。逐句和最差配对继续保留，所有14段输入、41对比较均已计分，重复提取误差为0。

## 自动复跑与后续边界

启动已启用 native 的 demo Omni 后：

```bash
env -u OMP_NUM_THREADS /root/miniconda3/envs/fd-sds/bin/python \
  scripts/check_demo_voice_cross_text.py --output NEW_DIR --prepare-only
env -u OMP_NUM_THREADS /root/miniconda3/envs/fd-sds/bin/python \
  scripts/check_demo_voice_cross_text.py --output NEW_DIR
```

脚本保留失败收据，成功后自动写出逐句/固定裁片 `manifest.json` 和短句聚合 `aggregation_manifest.json`。本轮补充方案已固化到脚本；用临时目录重建并逐样本比较，聚合 PCM、文本清单及41对比较与实际实验一致。

停止该实验 Omni、确认GPU空闲，再分别用 `scripts/check_demo_speaker_embeddings.py --manifest NEW_DIR/manifest.json --output NEW_DIR/speaker.json` 和聚合清单运行现有 LMFT 评测器；Python 环境见 `docs/demo_voice_rng.md`。原始音频、日志留在忽略目录，提交仅包含自造夹、指标和报告。已有31项相关测试通过。

当前自动迭代的约束是：同文可复现性继续独立检查；跨文本候选必须在同一文本/句长/seed清单上作配对比较，同时报告短句、长句、聚合、F0与ASR，不能只优化一个汇总 cosine。没有已知身份对照前不设“身份通过”阈值。本轮没有足够证据支持修改线上文本、拼接播放、重训练或增加每会话声学状态。

收据入口：`exp/web_demo/voice_cross_text_v1/{protocol,receipt,manifest,speaker,summary}.json`，探索性补充见同目录 `aggregation_*.json`。实验结束服务已停止，保留启动前的空闲状态。
