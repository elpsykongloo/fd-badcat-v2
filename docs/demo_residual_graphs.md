# Talker 残差预测优化与部署验收

2026-10-12：已采用完整序列长度的残差 Transformer 内部 CUDA Graph，正常启动流程默认启用。优化版服务于 09:12:39 UTC / 北京时间 17:12:39 恢复；随后已验证 HTTPS 登录、WebSocket `demo_ready`、原 chelsie/seed42 配置与正常流式协议。正常服务没有 profiling 接口。

## 结果与测量边界

同一台 RTX PRO 6000 Blackwell 96GB，原 BF16 模型、原声音、原 seed、原 codec 分块和四槽配置。每个方案运行 32 条实际 TTS 请求：6 条预热、18 条计时请求、2 条 seed43、2 条恢复 seed42、4 条并发请求；两组均 32/32 成功。计时主表使用 6 条自造中英文文本各重复 3 次的串行结果，中间一轮逆序；预热、seed 检查和并发请求不计入主表。采样期间未启用 profiler。

## 机制与声音、seed 检查

原本 seeded residual/MTP 外层为 eager，以保护每请求 Generator。新实现保留这个外层，在 `CodePredictorWrapper` 内部单独捕获确定性的 Transformer forward：固定 batch=1、长度17，使用现有稳定输入缓冲区和独立图内存池。15 次残差预测依次重放同一图；每次输出在同一流上消费完毕后才进行下一次重放。首次捕获在启动 TTS 预热时完成。

采样、top-k/top-p、softmax 和请求级 Generator 仍沿用原路径。投影、声码头、采样及循环控制仍在这张内部图之外；主 Talker 图和 Thinker 图照常工作。日志中的 `residual_batch=1 eager=true` 继续表示外层保护，并不表示内部没有图：新增日志为 `fd_demo_residual_inner_graphs mode=graph lengths=[17] sampling=eager`。

- 实际模型权重微基准：8 组输入分别使用 seed42/43，共16组；采用方案的残差声码数值与 RNG 消耗偏移均保持一致。未做文件完整性哈希或 PCM 逐字节验证。
- 完整 TTS：沿用原文约束和声音配置证明。6条文本优化前后的说话人嵌入 cosine 均约1；重复运行、seed43以及切回seed42的检查通过。
- 并发仍有基线已有的微小声音变化：基线同文本串行/并发 cosine 最低0.999870，候选最低0.999882。这些未校准为身份阈值，不能作为任意输入零差异或人工听感完全相同的证明。
- 生产重启后 seed42/43 各一条实际 TTS 成功，公共入口返回原 chelsie/seed42。公网探针首次未带 Origin 被正确拒绝，补充浏览器 Origin 后成功；未为探针放松入口检查。

## 图内计算与后续取舍

CUDA Graph 减少提交开销，图内矩阵运算仍全部执行。已有 trace 中 Talker 的四类 BF16 GEMM kernel 合计约386 ms，Thinker 解码的 MoE/GEMV 也占主要工作量；这些数字是此前单条请求的 kernel 累计时间，不能与本次墙钟中位数相减。

本次实际试过将残差 Transformer 的输入缩短为当前可见前缀，目的是减少图内重复计算。其微基准中位数10.757 ms，反而略慢于完整长度图的10.686 ms，且16组输入中1组残差声码发生变化；还增加约54秒首次编译。该方向未采用。样本表明单纯减少这段短序列长度没有带来额外收益；没有硬件计数器证据，不能因此直接认定显存带宽饱和。

更深入的增量 KV、矩阵算子重写或将采样也捕获进图，需要额外验证数值和 RNG 行为。本轮没有继续投入这些收益未明、调试成本较高的方向。FP8 与内部图重放可在后续组合部署时保留；没有同口径 FP8 速度实测，因此不宣称本优化收益高于 FP8，也不把两者收益直接相加。用户已验证 FP8 效果可接受，本轮没有重做量化质量论证。
